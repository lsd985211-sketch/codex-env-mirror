# startup Maintenance Surfaces

Authority: maintenance contracts for this system. Load this shard only
after the maintenance registry selects the system. The compact index at
`../maintenance_surface_map.md` is navigation only and does not duplicate
the contracts below.

| Surface | Owns | Does Not Own | Usual Entry |
| --- | --- | --- | --- |
| `state_write_authority.py` + `contracts/state_write_authorities.json` | Machine-readable authority for high-risk mutable state domains and field/path bindings: one active writer per logical fact, an explicit writer allowlist, a cross-platform atomic lease, monotonic domain and binding generations, shadow-equivalence receipts, old-writer freeze, fenced rollback, negative desired state, and a stable observed-state gate before mirror refresh or publish. It exposes the compact system-state information entry used to diagnose authority, bindings, writers, target convergence, and publication readiness. | Choosing a domain's business desired state, replacing domain reconcilers, serializing unrelated state behind a workspace-wide lock, accepting undeclared writers, transferring a `shadow_only` binding, reverse-absorbing Windows ambient state into Work Git, publishing the mirror, or mutating any source after the terminal publish. | `snapshot`, `validate`, `pre-publish [--stability-seconds N]`; binding API is owner-consumed; regression via `python _bridge\state_write_authority_tests.py` |
| `codex_config_guard.py` | Codex startup/config integrity plus separately reported provider-discovery and Desktop model-runtime compatibility diagnostics. It is the explicit maintenance owner for `codex-startup-and-provider.core`, exposes one machine-readable command contract, and keeps read-only snapshot/doctor/validate/metrics eligible for on-demand convergence. The stable WSL config resolves through the platform-owned `CODEX_HOME`; mutable provider, model catalog, and Statsig evidence resolves through the Windows Desktop host config and is never imported into the WSL baseline. It reports session-store state but delegates all automatic session compaction to the governed stopped-process pre-launch owner, avoiding competing writers and mismatched deadlines. Validation blocks only durable startup invariants while model/provider findings remain explicit advisory evidence | Treating dynamic active-workspace selection as a permanent invariant; storing Desktop build paths, provider selection, model selection, CC Switch state, or Statsig state in the recovery baseline; requiring every provider to implement `/v1/models`; using an unreferenced catalog as current authority; forcing one reasoning-effort set on every model; killing or restarting the active Desktop session; applying session compaction from the config guard | `command-contract`, `snapshot`, `doctor`, `repair-plan`, `validate`, `metrics`, `run-once` |
| `codex_desktop_protocol_compatibility.py` + `codex_appserver_model_bridge.py` | Read-only inspection of the signed Codex Desktop ASAR and isolated temporary app-server probes for deprecated-method notification compatibility. It distinguishes a completed vendor migration from the current native `deprecationNotice` opt-out bridge, is consumed by the governed launcher, and retains exact evidence that `thread/rollback` remains upstream-owned | Patching `app.asar`, inventing a replacement for `thread/rollback`, filtering unrelated notices, treating notification suppression as protocol migration, restarting Desktop, or writing real Codex sessions during validation | `codex_desktop_protocol_compatibility.py inspect\|validate`; startup facade in `start-codex-desktop-elevated.ps1`; regression via `codex_desktop_protocol_compatibility_tests.py` and `codex_startup_chain_tests.py` |
| `codex_plugin_runtime_doctor.py` | Bounded read-only classification of Codex Desktop plugin/runtime evidence: external app-server interrupts, native-addon initialization failures, remote catalog authentication limits, and rejected plugin metadata; preserves evidence references and package/version ownership | Patching signed `WindowsApps` content, replacing native addons, disabling unrelated plugins, treating the last stderr line as an exit cause, or making upstream optional-capability failures block startup | `snapshot`, `doctor`, `validate`; focused regression via `python _bridge\codex_plugin_runtime_doctor_tests.py` |
| `shared/process_liveness.py` | Side-effect-free cross-platform PID liveness and process-creation identity checks shared by startup, launcher, MCP, mirror, network lease, and background-refresh owners; creation identity distinguishes stale-lock PID reuse without signalling the process; includes a first-party unsafe-probe scanner | Process termination, process-tree cleanup, ownership decisions, application health checks, or probing protected processes beyond limited query rights | `python _bridge\shared\process_liveness_tests.py`; `python _bridge\codex_plugin_runtime_doctor.py validate` |
| `codex_session_store_doctor.py` | Codex local session-store restore-performance evidence and compression-only restart-boundary maintenance: bounded `.codex\sessions` sizing, largest/recent JSONL files, guarded in-place JSONL compaction of tool outputs/events/reasoning blobs, backup manifests, and metrics for restart/resume risk. It does not create continuation tasks, move sessions, archive sessions, or delete sessions. Automatic maintenance only runs while the Codex process family is stopped and only targets sessions at or above the risk threshold. Its non-blocking owner lock records PID plus process-creation identity, replaces only old locks proven dead or PID-reused, and keeps legacy or unverifiable live-owner locks fail-safe. | Creating continuation tasks for storage maintenance; moving, deleting, or archiving session files; hot-editing while Codex is running; compacting conversation messages or existing `compacted` context blocks; disabling MCPs; lowering model/tool capability; changing network/model/config routes | `snapshot`, `doctor`, `repair-plan`, `compact-plan`, `compact --confirm-compact`, `auto-maintain --apply`, `metrics`, `validate` |
| `codex_prelaunch_maintenance.py` | Bounded fail-open adapter used by the governed Codex Desktop launcher after the stopped-process boundary: starts `codex_session_store_doctor.py auto-maintain --apply --boundary pre-launch` without a console, enforces a finite timeout, consumes its JSON receipt, and permits Desktop startup after owner failure or timeout. | Selecting sessions, changing compaction thresholds, editing session files directly, launching Desktop, treating maintenance failure as a startup blocker, or replacing the session-store owner | `run --workspace <workspace> --timeout-seconds <seconds>`, `validate`; regression via `python -m unittest _bridge\codex_prelaunch_maintenance_tests.py` |
| `codex_runtime_cache_governance.py` | Cached dependency-runtime inventory, current/rollback retention, stale install-residue detection, and reversible manifest-backed quarantine | Deleting cached runtimes, moving the active runtime, changing providers/models, or touching Desktop/CLI package files | `snapshot`, `doctor`, `repair-plan`, `quarantine --apply --confirm QUARANTINE-OLD-RUNTIMES`, `validate` |
