## Memory Destination Matrix

Use this matrix when deciding where a captured observation should go. The
default for uncertain items is no long-term write.

| Input | Destination | Required Before Promotion | Verification |
| --- | --- | --- | --- |
| User preference or profile fact | user profile | explicit or repeated user signal, non-secret, not one-off task state | user-profile guidance selects it when relevant |
| Operational lesson or root cause | PMB or absorption index | current evidence, reusable behavior, incident details compressed | `recall-checks` plus `memory_governance.py validate` |
| Codex behavior constraint | global or workspace `AGENTS.md` | correct scope, no duplicate rule, mirror sync | `agents_rule_mirror.py validate` |
| Reusable procedure | skill or custom command proposal | repeatable inputs/outputs/boundaries | template render or skill gate dry-run |
| Skill routing observation | skill usage ledger or skill proposal | planned-vs-actual skill evidence, no sensitive task content | `skill_orchestrator.py usage-summary` plus targeted `SKILL.md` readback |
| Tool capability or fallback fact | MCP capability matrix or owning maintenance surface | current tool evidence, permission boundary preserved | tool matrix read-back and relevant doctor |
| External source knowledge | external knowledge evidence layer first | official/primary, scoped, reusable, non-sensitive | `external_knowledge.py doctor`, then distill plan |
| Current-task side issue | one-shot work note | valuable but non-blocking, safe to defer until main task completion; not an authorization grant | closeout reads raw note, processes read-only follow-up work, proposes any write separately, then clears it |
