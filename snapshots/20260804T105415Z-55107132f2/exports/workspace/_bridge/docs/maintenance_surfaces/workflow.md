## Long Command Receipt Consumption

## 效率循环投影

`workflow_efficiency_cycle_projection.py` 只读消费现有 rollout 与 Work Git owner receipt，生成六类受控 `EfficiencyCycle` 的脱敏计数、置信度和证据摘要哈希。它不保存原始用户正文、命令、路径、授权令牌或完整收据，不重解释授权、不推断业务接受，也不创建 daemon、数据库或第二个 review 队列。`workflow_observation_iteration.py` 仍是唯一 observer 写入与跨任务候选 owner；只有多个独立任务的重复循环才可进入既有 review 队列。saved closeout 可记录投影，`save=False` 仅 preview 且不得写 observer、review queue 或授权状态。

Callers must consume the underlying process/session until an exit code is
present. An outer tool cell ending is not a terminal command receipt. When the
transport cannot guarantee final output delivery, run the owner's single-call
`converge --intent-id <id> -- <command>` entry and let it return one terminal
receipt. `status` and `follow` are observation-only diagnostics and must not
be emitted as a machine next action or used to build a polling loop; `running`
and missing receipts cannot satisfy a workflow gate.
