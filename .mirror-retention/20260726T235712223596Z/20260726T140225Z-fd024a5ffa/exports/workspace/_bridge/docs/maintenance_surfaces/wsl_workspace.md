# wsl_workspace Maintenance Surfaces

Authority: maintenance contracts for this system. Load this shard only
after the maintenance registry selects the system. The compact index at
`../maintenance_surface_map.md` is navigation only and does not duplicate
the contracts below.

| Surface | Owns | Does Not Own | Usual Entry |
| --- | --- | --- | --- |
| `wsl_workspace_owner.py` + `wsl_workspace_generated_artifacts.py` + `wsl_interop_guard.py` | Long-lived WSL workspace lifecycle owner. Maintains the sole daily Work Git authority, Windows bare Git backing store, Desktop's persisted UNC project identity, exact Windows Git `safe.directory` admission, one exact user-PATH Git projection, and live Desktop Git-worker `stable-metadata` acceptance. It reports malformed machine PATH entries without broadly rewriting them and treats fixed-path Git success as supporting evidence only. It also owns declared WSL execution targets, a fixed-allowlist one-way host compatibility projection, and a bounded systemd timer that detects and restores a missing `WSLInterop` binfmt registration. Host projection supports repeated allowlisted `--include` selectors for a bounded deployment while another allowlisted surface is intentionally unresolved; it still uses routed backup, atomic replacement, and exact hash readback, and it preserves the prior full manifest until every unselected file is current so a directed success cannot masquerade as full convergence. The projection includes an atomic provider-runtime bundle so a Windows watcher cannot combine a current source decision with stale repair/config owners; its derived startup-baseline projection preserves host-owned state while retiring only the obsolete native project-config requirement; `validate` reports eligible hash drift as a risk. Work Git cleanup classifies only a fixed root-relative allowlist of ignored editor/test caches, refuses symlinks and type drift, and requires a separate confirmation; host cleanup separately classifies fixed regenerated or redundant artifacts outside the projection and blocks if the projection is stale. Guard installation uses routed external backup, atomic root-owned writes through the named WSL distribution, immediate repair, and exact readback. The former Windows workspace is a generated execution surface for Windows-only owners, never a source authority. Normal publication follows `WSL Work Git -> Windows bare Git -> validated mirror publish -> GitHub recovery repository` | Switching the default WSL distribution, identifying an unlogged historical binfmt writer, importing ambient Windows Codex runtime/secrets/sessions/SQLite/caches/plugins into Work Git, publishing mirror releases, replacing the mirror owner, sharing writable runtime state, reverse-copying host state into Work Git, broadly rewriting machine PATH, treating a fixed executable probe as Desktop acceptance, projecting files outside the declared allowlist, deleting bridge/runtime/user data, broad cache discovery, or managing Windows-only Office/GUI/browser/Weixin/OMEN/CC Switch sessions | `python _bridge\wsl_workspace_owner.py status|plan|validate|interop-guard-plan|interop-guard-apply --confirm INSTALL-WSL-INTEROP-GUARD|handoff|cleanup-plan|cleanup-apply --confirm PRUNE-WORK-GIT-GENERATED-ARTIFACTS|host-cleanup-plan|host-cleanup-apply --confirm PRUNE-WINDOWS-HOST-COMPATIBILITY|desktop-project-status|desktop-project-apply --confirm REGISTER-WSL-DESKTOP-PROJECT|host-projection-plan [--include <allowlisted-path>]|host-projection-apply --confirm PROJECT-WSL-HOST-COMPATIBILITY [--include <allowlisted-path>]|mirror-export --kind work-git-release`; bootstrap requires `--confirm BOOTSTRAP-WSL-WORKSPACE`; unified facade operations are `workspace_status|workspace_plan|workspace_bootstrap|workspace_validate|workspace_handoff|workspace_cleanup_plan|workspace_work_git_release` |
| `wsl_workspace_owner.py` host-audio migration + `shared/windows_runtime_assets.py` | Split-platform retirement boundary for the former Windows project tree. User-facing audio results are hash-verified into the WSL asset root, while GUI/OCR/audio GPU runtimes and models remain Windows-native under `%LOCALAPPDATA%\Codex`; the shared path authority keeps GUI MCP, mobile bridge, startup config, and skills aligned. Fixed ASR/Demucs/WAV intermediates and incomplete downloads are pruned only after classified migration. | Arbitrary host paths, opaque files, source deletion before hash match, symlink traversal, moving GUI/hardware runtimes into WSL, duplicating wheel stores, or treating a junction/config path as runtime health proof | `python _bridge\wsl_workspace_owner.py host-audio-migration-plan`; apply only with `host-audio-migration-apply --confirm MIGRATE-LEGACY-HOST-AUDIO-ASSETS`; validate Windows OCR/audio runtimes from their `%LOCALAPPDATA%\Codex` executables |
| `windows_execution_agent.py` | WSL-owned typed Windows execution plane. Inventories the fixed Codex scheduled-task set, validates `Limited` versus explicitly justified `Highest` lanes and non-SYSTEM principals, exposes only catalogued operation IDs, invokes an existing task without caller-supplied command arguments, and reports task-start acceptance separately from business completion. It is a one-shot bridge and adds no resident privileged listener. | Arbitrary shell or arguments, task creation, changing task ACLs/run levels, becoming a Windows SYSTEM service, replacing business owners, treating `schtasks /Run` success as operation completion, or writing back into Work Git | `python _bridge\windows_execution_agent.py status|validate|capabilities|invoke-plan --operation <id>|invoke --operation <id> --confirm RUN-WINDOWS-EXECUTION:<id>`; facade aliases: `python _bridge\wsl_workspace_owner.py windows-agent-*` |
| `work_git_change_owner.py` | Isolated task worktrees, declared-path commits, local Windows bare-Git branch synchronization, fast-forward-only integration into the WSL Work Git `main`, repository-safe configuration, local Git commit-graph/object maintenance, overlap checks, and structured receipts | Source editing, domain validation, runtime or generated state, mirror/GitHub publication, automatic conflict resolution, destructive reset, force-push, branch deletion, remote fetch/prune, or treating a commit as proof of owner compatibility | `snapshot`, `validate`, `start-plan|start --confirm START-WORK-GIT-TASK`, `commit-plan|commit --confirm COMMIT-WORK-GIT-CHANGESET`, `sync-plan|sync --confirm SYNC-WORK-GIT-BRANCH`, `integrate-plan|integrate --confirm INTEGRATE-WORK-GIT-TASK`, `config-plan|config-apply --confirm APPLY-WORK-GIT-SAFE-CONFIG`, `maintenance-plan|maintenance --confirm RUN-WORK-GIT-MAINTENANCE`; regress with `python -m unittest work_git_change_owner_tests.py` from `_bridge` |
