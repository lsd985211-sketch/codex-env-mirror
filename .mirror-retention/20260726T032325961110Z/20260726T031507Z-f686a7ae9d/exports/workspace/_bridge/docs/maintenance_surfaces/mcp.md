# mcp Maintenance Surfaces

Authority: maintenance contracts for this system. Load this shard only
after the maintenance registry selects the system. The compact index at
`../maintenance_surface_map.md` is navigation only and does not duplicate
the contracts below.

| Surface | Owns | Does Not Own | Usual Entry |
| --- | --- | --- | --- |
| `mcp_recovery_bundle_owner.py` + `mcp_recovery_bundle_manifest.json` | Single authority for MCP implementation recovery: validates platform, entrypoint, license, and authorization declarations; builds content-addressed offline archives without committing expanded dependency trees; verifies hashes and safe tar members; and separates source restoration, offline verification, owner reacquisition, remote reconnection, and missing-bundle blockers. Release import accepts a hash-bound archive reference to an earlier public milestone and downloads from that tag before normal local hash and tar-safety verification. The mirror consumes its readiness receipt | Treating source/config staging as executable MCP recovery, running package installation during restore, uploading private Windows runtimes or unauthorized upstream code, accepting archive escapes, trusting a referenced release asset without downloading and hash verification, publishing assets, activating MCPs, or marking remote/plugin MCPs ready without receipts | `python _bridge\\mcp_recovery_bundle_owner.py validate`, `readiness`, `build --bundle <id>`, `verify`; mirror `restore-plan` and `stage` consume readiness |
| `local_mcp_hub_owner_mcp.py` | Explicit read-only profile/tool allowlist for Hub-first OpenAI Docs, Context7, Microsoft Docs, filesystem-admin/filesystem, MarkItDown, and MySkills calls through existing fresh stdio; compact owner receipts retain the tool result, route, error, and permission contract while removing duplicated initialize/command/stdout transport data | Write tools, current browser/GUI/mobile sessions, permission expansion, dynamic route discovery, or replacing owner result content with count-only summaries | imported by `local_mcp_hub.py`; `python _bridge\local_mcp_hub.py validate`; OpenAI protocol smoke: `python _bridge\mcp_session_doctor.py smoke --profile openai-docs` |
| `codex_config_projection.py` | Field-ownership-aware, secret-free projection of live non-provider Codex settings with an explicit `windows_host` or `wsl` ledger scope. The sole per-runtime recovery ledger is `~/.codex/state/managed-config-projection.json`; active portable values are adopted, missing managed values are restored, explicit live values win conflicts, and known Desktop preferences use native setting readback/sync. A legacy or scope-mismatched ledger may contribute only portable fields during migration; platform-bound fields are re-adopted from the current same-platform config before the new scope is written. Windows keeps its native Desktop MCP, plugin, marketplace, notify, shell-environment, and Windows roots protected, while the WSL ledger removes those platform roots and delegates them to `wsl_codex_runtime.py`; project roots and Desktop environment selection are runtime-local in both scopes. CC Switch's current provider record is the sole model-catalog authority: `model_catalog_json` is never stored in the recovery ledger, providers without an active `settings_config.modelCatalog` remove stale catalog pointers, and providers with a catalog keep the live CC Switch projection. Retired `common_config_codex`, `codex_managed_projection_v1`, and provider `commonConfigEnabled` surfaces are removed and must remain absent | Selecting providers, copying auth/token material, recreating CC Switch common configuration, replaying a ledger across runtime scopes, owning WSL runtime-local invariants, preserving provider-derived catalog pointers across provider changes, silently deleting portable managed keys, directly editing Desktop global-state JSON, or overwriting explicit live values | `snapshot`, `doctor`, `plan`, `apply`, `validate`; guarded `apply --reseed-managed --confirm-reseed RESEED-MANAGED`; `codex_config_projection_tests.py`; automatic consumption by config guard and provider watcher |
| `mcp_session_doctor.py` + `mcp_session_profile_drift.py` | MCP config/protocol/current-turn evidence, gateway summary, and topology-aware negative-evidence classification. A closed task-local `node_repl` kernel becomes structured `session_bound_acceptance_pending` evidence and requires a real call from a new Desktop task; stateless MCP failures without a bounded fallback or healthy gateway remain blocking risks | Retrying or rebinding a closed task-local handle, treating config/protocol smoke as current-turn callability, weakening stateless MCP failure gates, business module health, memory content quality, or file backup policy | `validate`, `metrics`; focused classification regressions via `mcp_session_profile_drift_tests.py` |
| `mcp_session_doctor_routes.py` | Read-only CLI command dispatch helper for MCP session diagnostics; maps CLI command names to injected `mcp_session_doctor.py` handlers while preserving payload shaping | Observation storage, protocol smoke execution, gateway calls, route policy, permission/fallback semantics, or business diagnostics | consumed by `mcp_session_doctor.py`; validate with `mcp_session_doctor.py validate` and `local_mcp_hub.py validate` |
| `mcp_route_policy.py` | Classified `hub_first` / `session_native_first` / `owner_cli_first` precedence, required first step, same-boundary fallback ordering, and cross-surface stale-guidance checks | Tool execution, permission expansion, owner business state, or treating generic skill prose as stronger than a profile affinity | direct module validation; `mcp_capability_routes.py validate` |
| `mcp_profile_launcher.py` + `mcp_profile_launcher_process.py` / `mcp_lazy_stdio_proxy.py` | Windows-hidden MCP launch routing plus command-fingerprinted catalog caching for heavy stateful profiles. Lazy profiles enter the proxy loop in the launcher process instead of retaining a second waiting Python parent; Desktop still gets one lightweight task-bound stdio proxy and the guarded child still starts only on the first non-catalog call. Non-lazy profiles keep the existing guarded subprocess path. | Sharing a stdio child across tasks, bypassing target permissions, treating cached schemas as runtime health, changing non-lazy profile process semantics, or replacing `mcp_launch_guard.py` cleanup/supervision | `python _bridge\mcp_lazy_stdio_proxy_tests.py`; refresh with `python _bridge\mcp_profile_launcher.py <cdev|pw|gui|drawio> --warm-cache`; real-child smoke via `mcp_session_doctor.py protocol-smoke <profile>` |
| `local_mcp_hub.py` + `local_mcp_hub_process.py` + `shared/wsl_user_systemd.py` | Classified Hub-first entrypoints and the Hub's WSL user-systemd lifecycle on loopback with atomic backed-up unit installation. PMB calls are connection-only consumers of `codex-pmb-memory.service`; a missing token or transport failure returns the service owner entrypoint and never starts another daemon. | Owning-tool permissions, session-bound native identity, making the retired Windows checkout the primary Hub source, PMB daemon lifecycle, arbitrary unit management, or a global replacement for affinity selection | `python _bridge\local_mcp_hub_process.py plan|status|validate|install --confirm INSTALL-CODEX-LOCAL-MCP-HUB`; `python _bridge\local_mcp_hub.py validate|smoke`; focused process and PMB connection tests |
| `github_hub_client.py` | Hub GitHub REST credential chain: environment/App/Vault sources first, then the existing `gh` keyring token through a bounded in-process bridge when WSL Credential Manager access is unavailable; API responses retain source labels without secret values | Writing credentials, persisting or printing tokens, bypassing 403 permissions, replacing `github.gh`, or changing GitHub route affinity | consumed by `local_mcp_hub.py`; validate with Hub `github.api` and `github.gh`, plus `github_hub_client_tests.py` |
| `mcp_capability_routes.py` | Machine-first derived MCP route index, identity-weighted lookup, explicit browser-session coverage, and affinity-ordered fallback chains for Codex/tool orchestration | Human-facing explanation, replacing the Markdown matrix source of truth, permission changes, or scoring generic policy prose as capability identity | `build`, `lookup`, `validate` |
| `local_mcp_hub_graph_tools.py` with `local_mcp_hub.py` / `local_mcp_hub_specs.py` / `local_mcp_hub_catalog.py` | Hub-first, fresh-stdio adapters for the isolated WSL GitNexus and Graphify MCP servers. GitNexus forwards only upstream read-only tools; Graphify uses a fixed query-only allowlist because its current MCP catalog omits read-only annotations. Both constrain GitNexus cwd to Work Git and Graphify graphs to managed external state, terminate the child after each call, and remain visible in the default Hub catalog | Graph indexing/extraction, embeddings, graph generation, hooks, watchers, editor setup, config registration, external-model backends, global npm changes, arbitrary filesystem paths, or forwarding upstream mutating MCP tools | Hub `gitnexus.list_tools|call`, `graphify.list_tools|call`; focused `local_mcp_hub_graph_tools_tests.py` |
| `popup_window_doctor.py` | Codex/MCP console popup attribution for PowerShell/cmd/conhost parent chains | Disabling tools, killing processes, changing MCP capability, rewriting Codex app behavior | `snapshot`, `doctor`, `validate`, `metrics`, `observe` |
