# bridge Maintenance Surfaces

Authority: maintenance contracts for this system. Load this shard only
after the maintenance registry selects the system. The compact index at
`../maintenance_surface_map.md` is navigation only and does not duplicate
the contracts below.

| Surface | Owns | Does Not Own | Usual Entry |
| --- | --- | --- | --- |
| `wsl_codex_app_server.py` | Optional WSL-only Codex app-server owner. Generates one user-level systemd unit from the Linux Codex executable, keeps `CODEX_HOME` isolated, binds only `unix://%t/codex-app-server.sock`, and validates enablement, readiness, identity, and the unchanged Windows Desktop/CDP route. Installation is explicit and backed up through the WSL backup router; no token or Windows session state is copied. | Running as root/SYSTEM, selecting a Windows shim implicitly, listening on TCP, sharing Desktop databases or credentials, replacing the Desktop/CDP route, or treating a unit file as proof that the protocol is ready | `python _bridge\wsl_codex_app_server.py plan|status|validate|install --confirm INSTALL-CODEX-APP-SERVER|stop`; facade aliases: `python _bridge\wsl_workspace_owner.py codex-app-server-plan|codex-app-server-status|codex-app-server-validate|codex-app-server-install --confirm INSTALL-CODEX-APP-SERVER|codex-app-server-stop` |
| `mobile_openclaw_bridge/source_scan.py` | Source-only mobile bridge file inventory for governance scans. It excludes runtime profiles, attachments, logs, DB/WAL files, and backups so code analysis does not drown in bridge data. | Queue inspection, repair, file deletion, attachment analysis, runtime state mutation | `snapshot`, CLI `source-scan`, `source-scan --validate` |
| `mobile_openclaw_bridge/dashboard_state.py` | Read-only dashboard state payload assembly for `/api/state` and task detail views: task rows, user summaries, events, runtime display data, and status counts | HTTP routing, dashboard actions, permission decisions, queue mutation, retry/cancel/send behavior | `mobile_dashboard.load_state` facade |
| `mobile_openclaw_bridge/mobile_prompt_contract.py` | Mobile delegation prompt and marker contract: batch ids, ack/result marker codes, marker stripping, output contract lines, supplement contract lines, permission context embedding, and attachment prompt lines | Queue mutation, task routing, result polling/recovery, permission policy decisions, Weixin delivery, or MCP fallback execution | `mobile_openclaw_cli.task_prompt` facade plus protocol regression checks |
| `mobile_openclaw_bridge/codex_session_owned_result.py` | Bounded read-only recovery of exact non-placeholder `mobile_result` blocks from Codex rollout JSONL, including assistant/agent record filtering, duplicate-copy hashing, conflict fail-closed behavior with a bounded manual-review marker, and actual visible rollout/thread evidence | Queue mutation, static thread binding, task completion, retry policy, or Weixin sending | Audit with `mobile_openclaw_cli.py audit-owned-result-recovery --task-id <id>`; corrective apply is restricted to a pushed known-placeholder task and requires `recover-owned-result --task-id <id> --apply --confirm CORRECT-OWNED-RESULT --expected-sha256 <audit candidate_result_sha256>`. Sender-accepted correction receipts only finalize local state; an intent without a receipt requires manual review and is never auto-resent. Validate with `codex_session_owned_result_tests.py`, `owned_result_correction_tests.py`, `session_store_owned_result_fallback_check`, ownership/recovery checks, and sender idempotency checks |
| `mobile_openclaw_bridge/codex_cdp_route_process.py` | Hidden asynchronous submission of the existing governed Codex Desktop launcher for visible-CDP recovery. It preserves the requested CDP port and returns a process receipt without imposing a shorter caller deadline on startup maintenance. | CDP probing, process killing, waiting for Desktop readiness, retry policy, task delivery, or replacing the launcher singleton | Consumed by `codex_cdp_route.ensure_codex_cdp`; validate with `python -m unittest _bridge\mobile_openclaw_bridge\codex_cdp_route_process_tests.py` and CDP route regressions |
| `mobile_openclaw_bridge/mobile_maintenance_probe_policy.py` | Read-only maintenance probe policy primitives: quick/deep skipped payloads, deep-probe allowlist parsing, probe enablement checks, and compact timing wrappers | Running probes, reading queues/databases/processes, deciding issue actionability, repair planning, state mutation, or message delivery | consumed by `mobile_maintenance.inspect_system`; validate through maintenance summary/doctor and `code_maintainability.py validate` |
| `mobile_openclaw_bridge/mobile_mcp_fallback_client.py` | Fresh local stdio calls into the mobile MCP server for supplement `get_pending_batch` / `ack_message` fallback when the active Codex MCP transport is unavailable | MCP tool implementation, supplement business semantics, queue mutation outside the MCP server, native MCP replacement when current-turn callable | `mobile_openclaw_cli` fallback facades and `supplement-cli-fallback-check` |
| `mobile_openclaw_bridge/delivery_runtime_state.py` | Delivery retry and route recovery runtime state: retry cooldown policy, delivery retry markers, thread recovery markers, active route lease expiry, and diagnostic event coalescing | Dispatch execution, final reply sending, permission decisions, owned-result recovery, app-server repair execution, or task completion | `mobile_openclaw_cli` worker dispatch/recovery paths and retry/recovery regression checks |
| `mobile_openclaw_bridge/enqueue_command_cli.py` | OpenClaw inbound `enqueue` CLI command flow: control-message shortcut, capability passphrase reply handling, permission wait/reject branches, context-token attachment, queue enqueue, and immediate received/confirmation acknowledgements | Worker dispatch, final reply generation, permission policy decisions, attachment materialization internals, or queue schema ownership | `mobile_openclaw_cli.main` facade and enqueue/control/capability regression checks |
| `mobile_openclaw_bridge/mcp_dispatch_gate.py` | Read-only current-session MCP gate decision before hidden Codex app-server dispatch creates another turn | MCP repair, process cleanup, retry scheduling, queue mutation, or delivery execution | `mobile_openclaw_cli` worker dispatch path and route/gate regression checks |
| `mobile_openclaw_bridge/thread_prewarm_state.py` | Codex app-server thread prewarm runtime marker helpers: cooldown/budget config readers, `thread_prewarm:*` marker read/write, and prewarm scheduling audit event | App-server probing, background process startup, dispatch decisions, retry scheduling, or task queue lifecycle | `mobile_openclaw_cli` worker dispatch path and thread prewarm regression checks |

| `mobile_openclaw_bridge/worker_active_recovery.py` | Worker active-task recovery sub-stages: stale `queued_for_codex` recovery, queued materialized-turn rehydration, same-route active-owner protection, and queued-only recovery result shaping | Sent/processing result polling, final reply delivery, supplement ownership, permission decisions, app-server repair execution, or worker dispatch selection | `mobile_openclaw_cli.recover_active_codex_tasks` facade and active recovery / rehydrate / route fairness regression checks |

| `shared/long_command_receipt.py` | Submit-once local command lifecycle, deterministic intent-to-task identity, command/cwd/timeout execution signatures, matching running or terminal receipt reuse, one quiet follow process, bounded stdout/stderr projection, timeout cleanup, and durable result artifacts | Shell parsing, command authorization, permission escalation, resident supervision, retries, scheduling, replacement of the command's business owner, short status polling loops, or resubmitting a business command to discover completion | `python _bridge/shared/long_command_receipt.py submit --intent-id <id> -- <command>` then consume one `follow --task-id <id>` native handle; validate via `python _bridge/shared/long_command_receipt.py validate`; regress via `python -m unittest _bridge/shared/long_command_receipt_tests.py` |
